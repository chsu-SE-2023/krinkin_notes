#### UML

В 1996 был предложен унифицированный язык моделирования - UML, стандартизовавший все модели. Объединяет вместе несколько моделей: _модель использования, логическую модель, модель реализации, модель процессов, модель развёртывания_.

**Модель использования** - представляет собой описание функциональности ПО с точки зрения пользователя.
**Логическая модель** - описывает ключевые абстракции ПО (классы, интерфейсы и т.п.), т.е. средства, обеспечивающие требуемую функциональность.
**Модель реализации** - определяет реальную организацию программных модулей в среде разработки.
**Модель процессов** - отображает организацию вычислений и оперирует понятиями _процессы_ и _"нити"_. на позволяет оценить производительность, масштабируемость и надёжность ПО.
**Модель развёртывания** - показывает особенности размещения программных компонентов на конкретном оборудованию.

Всего UML предлагает **9 диаграмм**:
- диаграммы вариантов использования;
- диаграммы классов;
- диаграммы пакетов;
- диаграммы последовательности действий;
- диаграммы кооперации;
- диаграммы деятельности;
- диаграммы состояния объектов;
- диаграммы компонентов;
- диаграммы размещения.

#### Модель вариантов использования

![[Drawing 2026-09-11 12.34.41.excalidraw]]
С неё начинается разработка ПО. 

**Варианты использования (use cases)** - астпекты поведения ПО. Характерные процедуры применения разрабатываемого ПО конкретным пользователем. В качестве пользователя может выступать не только человек, но и другое ПО. Каждый вариант использования связан с какой-либо целью, имеющей самостоятельное значение, например возможность формирования оглавления в текстовом процессоре, но не просто набор текста.

В зависимости от цели варианты использования делятся на типы:
- _Основные_ - осбеспечивают требуемую функциональность ПО
- _Вспомогательные_ - Выполнение необходимых настроек системы и её обслуживание
- _Дополнительные_ - обеспечивают дополнительные удобства для пользователя

Деление довольно условное. Вариант использования можно описать кратко или подробно. Кратко: _название, цель, действующее лицо, описание, тип_.
Основные варианты обычно описываются подробно. Подробная форма включает себя всё из краткой, а также описание типичного хода событий и возможных альтернатив.

Типичный ход событий:

| Действие выполнителя | Отклик системы |
| -------------------- | -------------- |
| 1. ...               | 2. ...         |
| 3. ...               | 4. ...         |
