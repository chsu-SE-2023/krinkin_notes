**Система управления базами данных (СУБД)** - комплекс языковых и программных средств, предназначенных для создания, ведения и совместного использования баз данных многими пользователями.
#### Функции СУБД

- Должны поддерживать логически согласованный набор файлов;
- Должны обеспечить язык манипулирования данными;
- Восстанавливать информацию после сбоев;
- Поддерживать параллельную работу нескольких пользователей;
#### Задачи СУБД

- Непосредственное управление данными во внешней памяти;
- СУБД обращается к внешней памяти для хранения базы данных и для служебных целей (для ускорения доступа);
- СУБД использует как возможности файловой системы, так и напрямую обращается к данным;
- Управление буферами ОЗУ;
- Управление **транзакциями** - последовательности операций над базой данных, рассматриваемых СУБД как единое целое. Транзакция либо успешно выполняется и СУБД фиксирует изменение базы данных, произведённое этой транзацией, либо ни одно из этих изменений не отражается на состоянии базы данных. На основе транзакций поддерживается логическая целостность баз данных. Транзакция воспринимается как единица взаимодействия пользователя;
- Журнализация. Одно из требований к СУБД - обеспечить надёжность хранения данных: она должна быть в состоянии восстановить последнее согласованное состояние базы данных после любого аппаратного или программного сбоя. Для восстановления баз данных нужна дополнительная информация. Избыточная информация в **журнале изменений** базы данных. **Журнал изменений** - особая часть базы данных недоступная пользователям СУБД, поддерживаемая с особой тщательностью (иногда поддерживаются две копии журнала). Журнал содержит записи обо всех изменениях основной базы данных. Существует два вида журналов - локальный и общесистемный. После мягкого сбоя используется локальный журнал, после жёсткого сбоя - общесистемный или копия базы данных. 
  > "Журнал базы данных - аббревиатура ЖЖ." - Селяничев О.Л.
- Поддержка языков баз данных. Язык управления базами данных - **SQL** (Structured Query Language). _SQL = DDL (Data Definition Language) + DML (Data Manipulation Language) + DQL (Data Query Language) + ..._ 
#### Типовая организация современной СУБД

- Внутренняя часть называется **ядро СУБД** (DBE - DataBase Engine). Ядро отвечает за управление данными во внешней памяти, управление ОЗУ, управление транзакциями, журнализацию. Обладает собственным интерфейсом, недоступным пользователю, но используется в программах;
- Компилятор языка. Проблема современных СУБД в том, что язык SQL не процедурный, поэтому компилятор должен решить как выполнить оператор прежде чем произвести программу. Результат компиляции представляется или в машинных кодах, или во внутреннем машинонезависимом коде;
- Подсистема поддержки времени выполнения - направлена на выполнение машинонезависимого кода. Работает как интерпретатор;
- Набор утилит - процедуры, которые накладно выполнять с использованием языка баз данных: загрузка, выгрузка базы данных, сбор статистики, проверка целостности и др;
#### Ранние подходы к организации баз данных

Они исторически предшествовали реляционным СУБД. На основе методов, использованных в них организованы реляционные СУБД. Их знания полезны при определении путей развития. 

**Общие характеристики**
- Использовались давно и долго, накоплены громадные базы данных. Их нужно использовать совместно с современными;
- Не строились на абстрактных моделях;
- Был воплощён интерактивный доступ на уровне записей. Это требовало писать прикладные программы со своим интерфейсом доступа к данным.

**Ранние СУБД**
- Система основанная **на инвертированных списках** - организация доступа к данных из этих СУБД применяется в современных в виде индексов. Структура данных похожа на реляционную, но таблицы и пути доступа к ним видны пользователям. При этом строки таблиц упорядочены в некоторой физической последовательности. Могло быть определено произвольное число **ключей поиска** - по ним и строятся индексы, автоматически поддерживаются системой и видны пользователям. Правило ограничений целостности не существовало - программист должен был следить за этим свойством баз данных;
- **Иерархические СУБД** - сегодня существует много подобных баз данных. Такие базы данных состоят из упорядоченного набора **деревьев**. Дерево состоит из одной корневой записи и упорядоченного набора поддеревьев. Каждое дерево - иерархически организованный набор записей. **Запись-потомок** должен иметь <u>одного предка</u>. Все потомки с общим предком называются *близнецами*. Отслеживалась целостность ссылок между предками и потомками - никакой потомок не может существовать без родителя. ;
- **Сетевые СУБД** - CODASYL (комитет по языкам программирования) - конференция, на которой договорились о форматах данных: новый сетевой подход это расширение иерархического. В сетевой структуре потомок может иметь любо число предков. Сетевая база данных из записей и связей между ними. Связь определяется для двух записей: предка и потомка.

**Преимущества**: развитые средства управления данными в ВЗУ на низком уровне, возможность построения вручную эффективных прикладных программ, возможность экономии памяти засчёт разделения объектов.
**Недостатки**: слишком сложно пользоваться, необходимы знания физической организации данных, от физической организации зависят прикладные системы, логика взаимодействия с базами данных перегружена деталями доступа к элементам базы.
