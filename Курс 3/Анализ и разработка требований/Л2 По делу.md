Чем сложнее задача, тем сложнее программное обеспечение.
Факторы увеличения сложности:
- Сложность формального определения требований - большое количество факторов, разработчики не являются специалистами в предметной области заказчика, требования могут быть размытыми.
  ![[Drawing 2026-02-17 14.11.18.excalidraw]]
- Отсутствие удовлетворительных средств описания поведения дискретных систем с большим числом состояний при недетерминированной последовательности входных изменений
- Коллективная разработка
- Необходимость увеличения степени повторяемости кода

#### Блочно-иерархический подход в создании сложных систем

Любую сложную систему можно представить в виде дерева, когда конечный объект делится на множество блоков, которые также делятся на блоки.

Также применяется локальная оптимизация - определяется на сколько блоков на уровне будет разбита программа.
#### Жизненный цикл и его модели

**Жизненный цикл информационных систем** - Это базовое понятие методологии проектирования информационных систем. 

**Жизненный цикл** - это непрерывный процесс, который начинается с момента принятия решения о необходимости создания программного обеспечения и заканчивается в момент полного изъятия из эксплуатации.
**Жизненный цикл** - интервал времени от идеи (требование заказчика) до прекращения сопровождения.

**Документ, регламентирующий жизненный цикл** - международный стандарт ISO/IEC 12207.

![[Drawing 2026-02-17 14.39.31.excalidraw]]

Структура жизненного цикла базируется на трёх группах процессов:
- Основные процессы
	- Приобретение (оборудования, инструментов)
	- Поставка (оборудования, инструментов)
	- Разработка
	- Эксплуатация
	- Сопровождение
- Вспомогательные процессы
	- Документирование 
	- Управление конфигурацией
	- Опеспечение качества
		- Верификация - проверка состояния информационной системы на определённом этапе
		- Аттестация
		- Совместная оценка
		- Аудит
	- Разрешение проблем
- Организационные процессы
	- Управление проектом
	- Создание инфраструктуры проекта
	- Определение, оценка и улучшение жизненного цикла
	- Обучение

Каждый процесс характеризуется задачами, методами их решения, исходными данными, полученными на предыдущем этапе и результатами.

В разработку входят (ГОСТ 19.102-77 "Стадии разработки"):
- Постановка задачи
- Формирование спецификаций
- Детальное проектирование
- Кодирование
- Итеграция в существующие системы
- Тестирование
- Установка на оборудование заказчика
- Приёмка

#### Модели жизненного цикла

Сегодня известны две основные модели жизненного цикла:
- Каскадная модель (1970-е - 1985)
- Спиральная модель (1986 - 1990-е)
###### Каскадная модель

Ранее приложение представляло собой единое целое. Для разработки подобного ПО была предложена каскадная схема.

![[Drawing 2026-02-17 15.49.56.excalidraw]]
Пока не реализован один этап, не должен будет начат другой.

Достоинства:
- Хороша для информационных систем для которых точно и полно сформулированы все требования. 
- Выполняемые в логической последовательности этапы позволяют планировать сроки и затраты.
- На каждом этапе формулируется законченный набор документации

Недостатки:
- Реальный процесс разработки ПО не укладывается в эти жёсткие требования.
- Нет возможности пересмотра решений и возврата назад.

Не подходит для учебных проектов.

Основной недостаток каскадного подхода - запаздывание в получении результатов, согласование результатов с пользователем производится только в точках, планируемых после завершения каждого этапа. Требования к ПО заморожены в виде ТЗ на всё время её создания. Эти проблемы решены в спиральной модели жизненного цикла.
###### Спиральная модель

![[Drawing 2026-02-17 15.54.34.excalidraw]]
Каждый виток спирали соответствует созданию фрагмента или версии ПО. На нём уточняются цели и характеристики проекта, определяется его качество и планируется работа следующего витка.
Разработка итерациями отражает объективно существующий спиральный цикл создания систем. 
Неполное завершение работ на каждом этапе позволяет переходить на следующий не дожидаясь полного завершения работ на текущем. Недостающую работу можно выполнить на следующей итерации.
Главная задача быстрее показать пользователю рабочий продукт. Этим активизируя процесс уточнения, дополнения требований.

Основным недостатком является то, что момент перехода на следующий этап является не очевидным. Для его решения вводят временные ограничения на каждый этап жизненного цикла. Переход осуществляется в соотвествии с планом, даже если работа не закончена. План составляется на основе статистических данных, полученных из других проектов или своего опыта.

#### Система автоматизированного проектирования (CASE)

Первый уровень:
- Основные усилия на анализ и проектирование
- Быстрое итерационное прототипирование
Второй уровень:
- Автоматическая генерация кодов
- Автоматическая генерация документации
- Автоматический контроль проекта
- Сопровождение спецификаций проектирования

Примеры:
- BPWin - CASE система первого уровня
- ERWin - CASE система второго уровня
- Rational Rose - CASE система второго уровня

#### Оценка качества процессов жизненного цикла ПО

Предполагается что если процессы жизненного цикла будут произведены качественно, то и само программное обеспечение будет качественным.

В **ISO 9000** описаны необходимые условия для достижения некоторого минимального уровня организации процесса.

В **CMM** определяется пять уровней зрелости организаций-разработчиков:
1. _Начальный уровень_ - не существует условий для создания качественного программного обеспечения.
2. _Повторяемый уровень_ - внедрены технологии управления проектами, существуют стандарты и группа опеспечения качества.
3. _Определённый уровень_ - стандартный процесс создания и сопровождения программного обеспечения полностью документирован, существует процесс обучения.
4. _Управляемый уровень_ - внедрены качесвенно-количественные показатели
5. _Оптимизирующий уровень_ - постоянное улучшение существующих процессов. Довольно редко встречается.
