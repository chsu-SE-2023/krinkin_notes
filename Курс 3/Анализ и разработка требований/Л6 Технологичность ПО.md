**Технологичность** - качество проекта программного продукта, от которого зависят трудовые и материальные затраты на реализацию и последующую модификацию.

Факторы технологичности:
- Проработанность моделей
- Независимость модулей
- Стиль программирования
- Повторное использование кода

Результат хорошей технологичности:
- Четкое определение подзадач
- Ясная структура данных
- Снижение вероятности ошибок
- Упрощение внесения исправлений

Критерии оценки модулей:
- Сцепление модулей - мера взаимозависимости модулей:
	- По данным
	- По образцу
	- По управлению
	- По общей области данных
	- По содержимому
	Последние два лучше избегать
- Связность модулей - мера прочности соединения элементов модуля:
	- Функциональная
	- Последовательная
	- Информационная
	- Процедурная
	- Временная
	- Логическая
	- Случайная
	Перечислены в порядке уменьшения здравого смысла. Рекомендованы первые три.

Сцеплений должно быть как можно меньше, а связность внутри модулей должна быть как можно больше.

Подходы к проектированию:
- Нисходящий - сначала описывается большой модуль, а потом маленькие подмодули
- Восходящий

Методы реализации нисходящего подхода:
- Иерархический:
	- Разработка строго по уровням
	- Использование заглушек
	- Основная масса модулей разрабатывается в конце
- Операционный:
	- Учитывает последовательность выполнения при запуске
	- Сложность в начале работ
	- Ранняя разработка модулей вывода
- Комбинированный:
	- Достижимость модуля
	- Зависимость по данным
	- Возможность вывода результатов
